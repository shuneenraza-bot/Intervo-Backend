# Run a full interview

Everything below runs in PowerShell against the local server. It uses the seeded demo candidate. Interactive Swagger at http://localhost:8000/docs does the same thing: click **Authorize**, paste the token, then call the endpoints in order.

## 0. Once

```powershell
alembic upgrade head          # adds the interview columns
python -m scripts.seed        # roles, questions, criteria, rules, demo accounts
uvicorn app.main:app --reload --port 8000
```

`AI_PROVIDER=gemini` with a `GEMINI_API_KEY` in `.env` uses Gemini. With `AI_PROVIDER=rules`, or if Gemini fails for any reason, the rule-based evaluator answers instead. Every answer says which one was used in `provider`.

## 1. Sign in

```powershell
$api = "http://localhost:8000/api"
$step = Invoke-RestMethod "$api/auth/login" -Method Post -ContentType "application/json" `
  -Body '{"email":"ayesha@intervo.demo","role":"candidate","password":"Demo@1234"}'
# Step 2 is the face. Without a browser, send a fixed 276-number template (the demo script does the same).
$template = @{ v = 2; method = "landmarks"; features = @(0..275 | ForEach-Object { 0.3 + ($_ % 23) * 0.05 }) }
$pending = @{ Authorization = "Bearer $($step.pendingToken)" }
if ($step.faceEnrolled) {
  $body = @{ template = $template; liveness = @{ blink = $true } } | ConvertTo-Json -Depth 5
  $login = Invoke-RestMethod "$api/auth/face/verify" -Method Post -Headers $pending -ContentType "application/json" -Body $body
} else {
  $body = @{ template = $template } | ConvertTo-Json -Depth 5
  $login = Invoke-RestMethod "$api/auth/face/enroll" -Method Post -Headers $pending -ContentType "application/json" -Body $body
}
$h = @{ Authorization = "Bearer $($login.token)" }
```

Sign-in needs the password and then the face. The first time, the account has no face, so the second call enrols this template; later runs verify it. This enrols a made-up face on the demo account, which is fine for a demo.

## 2. Start

Send `roleId` **or** `jobId` (not both), a `mode` (`text`, `voice`, `video`) and a `count`.

```powershell
$iv = Invoke-RestMethod "$api/interviews" -Method Post -Headers $h -ContentType "application/json" `
  -Body '{"roleId":"frontend","mode":"text","count":4}'
$iv.questions | Select-Object id, skill, type, reason, question
```

`reason` is why the question was picked: `weakness` (persistent weak skill), `gap` (CV vs the role or job), `role` (highest-weighted skill) or `general`. There is always one behavioural question. Skills without a question template get one generated by Gemini and saved as a template marked `generated`.

## 3. Answer each question

```powershell
$q = $iv.questions[0]
$body = @{ questionId = $q.id; answer = "I use flexbox and grid with media queries, mobile first." } | ConvertTo-Json
$r = Invoke-RestMethod "$api/interviews/$($iv.id)/answers" -Method Post -Headers $h -ContentType "application/json" -Body $body
$r
```

You get `score` (0 to 100, calculated on the server from the admin criteria weights), `criteria`, `tips`, `provider` and `needsFollowUp`. `indicators` (video cues) can be sent in the body too.

## 4. Follow-up (only if `needsFollowUp` is true)

`needsFollowUp` is true when the evaluator asks for it or `completeness` is below `scoring_rules.followUpBelow`. `$r.followUp.question` is the question to show. The original answer and the follow-up are scored together:

```powershell
$f = @{ answer = "For example, on my FYP I used a 12-column grid and a breakpoint at 768px. As a result it worked on phones." } | ConvertTo-Json
Invoke-RestMethod "$api/interviews/$($iv.id)/answers/$($r.answerId)/follow-up" -Method Post -Headers $h -ContentType "application/json" -Body $f
```

Repeat steps 3 and 4 for the other questions. A question can be answered once, and a follow-up once.

## 5. Finish

```powershell
$done = Invoke-RestMethod "$api/interviews/$($iv.id)/finish" -Method Post -Headers $h
$done.score; $done.summary
```

The session score is the average of the answered questions; skipped ones are dropped. The status becomes `completed`, and only then does the session count for progress and for employers.

## 6. History and progress

```powershell
Invoke-RestMethod "$api/interviews" -Headers $h                 # your history
Invoke-RestMethod "$api/interviews/$($iv.id)" -Headers $h       # one interview with answers and tips
Invoke-RestMethod "$api/progress" -Headers $h | ConvertTo-Json -Depth 6
```

`/progress` returns per-skill `avg`, `trend`, `sessions` and `weak` (average below `weakThreshold` in at least `weakMinSessions` sessions), the `scoreTrend` for the chart and the `weaknessProfile` with each skill's coaching tip. Run two more interviews with short answers on one skill and it becomes weak, then shows up first in the next interview's questions.

Other candidates' interviews return `404`.
